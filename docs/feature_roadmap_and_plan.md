## 一、 已交付里程碑功能 (Milestone Delivered)

### [FEAT-01] 全机房主动自治巡检与《运行健康研判简报》生成
* **当前状态**：**✅ 已完成并全量测试通过 (v1.1.0)**
* **功能概述**：
  * **双轨触发**：大盘全景态势控制台集成带有雷达脉冲动效的「发起全网自治体检」按钮；左侧 AI 对话框支持自然语言口语化触发（“机房巡检”、“全网体检”、“生成健康简报”等）；
  * **闭环自治**：自动遍历在册核心设备探针，识别核心温度超 40℃ 红线或掉线异常；结合 RAG 向量规程库检索安全条例，自动防重复调用工单工具写入 SQLite 数据库，工单大盘无感实时联动；
  * **权威简报呈现**：出具通透磨砂玻璃微光的《高校实验室 IT 基础设施运行健康研判简报》模态弹窗，集成 SVG 环形进度态势仪表、四大核心 KPI、异常设备明细、条例溯源、工单穿透跳转、Markdown 一键复制与原生 `@media print` 打印优化；
  * **交付产物**：后端业务内核 `patrol_service.py`、工具 `patrol_tools.py`、前端弹窗 `PatrolReportModal.vue`、全量 129 项单元与集成测试、免安装便携整合包同步流水线。

## 二、 候选功能详细规划 (按答辩价值与业务深度分级)

### 【梯队一：答辩视觉王牌与资产拓扑 (高视觉冲击力)】

#### 1. [FEAT-02] 机房机柜 2D 机位拓扑视图 (Rack Layout View)
* **背景痛点**：
  * 后端数据库已内置规范的 `ServerRoom` 表（机房编号、机柜总数、配电额定功率、责任教师）以及资产表中的具体物理机柜位置（如 `实训楼201-机柜A01`）；
  * 目前前端只通过表格展示，评委无法直观感知机房机架真实物理空间分布与机位占用率。
* **设计方案**：
  * 在右侧看板新增「机柜拓扑」子视图；
  * 采用原生轻量 CSS Grid / SVG 绘制 42U 标准服务器机柜外观，直观渲染各机柜各 U 位的设备占用插槽；
  * 每个插槽附带健康呼吸灯（绿-良好、黄-预警、红-超温、灰-离线）；
  * 点击任意机位插槽直接联动呼出 `DeviceDetailModal` 硬件物理台账，并可一键发起排查。
* **激活底座**：`server_rooms` 表、`assets.location` 字段。
* **预估工期**：约 1.5 天（轻量前端为主，无外部重型 3D 引擎负担）。

#### 2. [FEAT-03] 运维工单流转与资产履历时序时间轴 (Timeline Drawer)
* **背景痛点**：
  * 后端数据库已有 `TicketWorkflow`（工单流转表：记录前置/后置状态、处置人、说明）和 `AuditLog`（行为审计表）；
  * 目前前端工单表格仅展示当前静态终态，缺乏完整的“流转脉络历史（Audit Trail）”，无法直观体现高校运维的闭环可追溯性。
* **设计方案**：
  * 在工单列表操作栏或设备详情弹窗中，新增「流转时间轴」按钮，点击从右侧滑出微光 Timeline 抽屉；

  * 彻底体现企业级软件工程的“可追溯、防抵赖、有迹可循”。
* **激活底座**：`ticket_workflows` 表、`audit_logs` 表。

### 【梯队二：业务规则深化与知识透明化 (增强业务可信度)】

#### 3. [FEAT-04] 规章规程知识中心 (RAG 向量库可视化与切块管理)
* **背景痛点**：
  * 底层已有 `KnowledgeDocument`（规程源文档表）与 `KnowledgeChunk`（切块台账表，包含切块文本、Token 数、Chroma 索引 ID）；
  * 目前 RAG 在系统中是“后台黑盒”，评委看不见规程切块分词细节，缺乏对“知识检索增强”的直观可信度。
* **设计方案**：
  * 右侧看板新增「知识规程」Tab；
  * 以卡片形式展示系统在册条例（如《高校实验室用电安全规范》《温控超标应急处置预案》《高功耗GPU准入条例》）；
  * 点击展开文档的分块（Chunks）明细抽屉，展示分块索引、章节层级、内容摘要及所属 Chroma 向量 ID；
  * 支持管理员在线上传/编辑新 Markdown 规章并一键重新向量化。
* **激活底座**：`knowledge_documents` 表、`knowledge_chunks` 表、ChromaDB。
* **预估工期**：约 1.0 天。
* **决策与排期**：

#### 4. [FEAT-05] 资产借用超期智能预警与 Agent 催还督促通知
* **背景痛点**：
  * `AssetBorrowLog`（借调流转表）中已预设了 `expected_return_time`（约定归还时间）与 `OVERDUE` 状态枚举；
  * 目前高校设备出借后经常发生学生或科研团队逾期未还、难以追踪的情况。
* **设计方案**：
  * 资产台账与全景概览中自动计算并高亮标红“超期借用设备”；
  * 超期设备操作栏新增「一键催还」按钮：Agent 自动提取借调人实名、学号/工号、借用天数，按公文规范自动起草一份《设备超期归还催告通知函》；
  * 支持一键复制、打印，或在对话流中展示催办提醒。
* **激活底座**：`asset_borrow_logs` 表、`users` 表。
* **预估工期**：约 0.5 天。

#### 6. [FEAT-07] 浏览器原生语音交互与高危告警 TTS 播报
* **背景痛点**：
  * 答辩现场或巡检演示时，纯键盘打字缺乏抓人眼球的声光互动感。
* **设计方案**：
  * **语音输入（STT）**：基于浏览器原生免外部依赖的 `webkitSpeechRecognition` / `SpeechRecognition`，输入框集成麦克风图标，按住说话即可自动转为文字填入输入框；
  * **高危语音播报（TTS）**：基于原生 `window.speechSynthesis`，当全网巡检发现严重超温告警或高优先级工单生成时，系统以干练的语音播报：“警告，检测到2号服务器温度达到43.5度，已触发紧急工单”。
  * **极简原则**：完全依赖浏览器内置能力，后端零外部重型依赖，便携包零体积增加。
* **激活底座**：Web Speech API。
* **预估工期**：约 0.5 天。
* **决策与排期**：
